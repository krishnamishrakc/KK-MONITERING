# KK Monitoring — Android Refresh Source Pack (V70)

This package is based on the user's updated PC **KK_Monitoring_V69** source. The existing study, mock, tracker, analytics, Learn Hub and Firebase modules remain in `index.html`, `app.js`, `app.css` and `assets/`. The Android-facing experience is a separate responsive shell and theme; it does not replace the core app logic.

## What's implemented in this pack

- A new iOS-inspired, premium dark glass mobile shell with floating bottom navigation, drawer navigation, safe-area spacing, restrained transitions and subtle active states.
- A Digital Wellness view and Today-card with app usage, last-seven-day chart, app classification, target settings and rule-based suggestions.
- User-editable Study / Mixed / Distraction categories. Initial classification: Guidely, Testbook, Yes Officer, Learning Capsule and Mahendras => Study; YouTube and Telegram => Mixed. All other apps start as Distraction, but can be changed.
- A provisional 100-point Productivity Score using 35% study signal, 25% recent mock/quiz accuracy, 20% seven-day consistency and 20% digital wellness. The study signal uses the higher of Focus Timer time and apps categorised as Study; it does not sum them because the two time sources can overlap. Missing inputs are excluded and remaining weights are renormalized; the UI identifies an incomplete score as provisional.
- Cloud-ready daily snapshots in `appData.digitalWellness`. The existing cloud payload already serializes `appData`; `mergeData()` now merges daily snapshots/categories/limits without discarding the other device's days.
- A Capacitor 6 Android native patch for UsageStats access, app usage summaries and optional Focus Guard. The service observes only app package names, with `canRetrieveWindowContent=false`, and includes an emergency pass and end-session action.
- Responsive treatment for wide tracker tables and the Daily Study Logs table to prevent text overlap on phone screens.

## Apply to your existing GitHub Android project

1. Make a full backup of your current GitHub repo and data export.
2. Copy the web files from this folder (`index.html`, `app.js`, `app.css`, `android-theme.css`, `android-shell.js`, `digital-wellness.js`, `assets/`, plus icons/manifest if present) into the web root used by Capacitor (`www/` is generated by `npm run build` here).
3. This source pack includes a GitHub Actions workflow that creates a fresh Capacitor Android project, applies the native UsageStats/Focus Guard patch, and builds a debug APK. Upload the contents of this ZIP to the root of a new GitHub repository (or a dedicated branch/repository for this Android refresh).
4. In GitHub, open **Actions → Build KK Monitoring Android APK → Run workflow** (or push to `main`). Download the `kk-monitoring-debug-apk` artifact when the workflow completes.
5. For a local build, install Node.js and Android Studio/SDK, then run:

   ```bash
   npm install
   npm run build
   npx cap add android
   npm run android:prepare
   npx cap sync android
   cd android && ./gradlew assembleDebug
   ```
6. Install the debug APK on your phone and test `TESTING_CHECKLIST.md`.

If you are merging into your old GitHub repo instead, first make a full backup. Keep your existing Firebase settings and application ID. Do not overwrite a release signing key or blindly replace the old `android/` folder. The included workflow generates a clean Android wrapper from this pack; it is not a signed release APK.

## Phone usage reporting notes

Android UsageStatsManager requires the special Usage Access setting. The native patch uses `UsageStatsManager` and `EventStats` screen-interactive totals (Android 9/API 28+); on earlier versions screen-interactive totals are left unavailable while app foreground usage may still be reported. App foreground duration and screen-interactive time are separate metrics, so the app shows both separately. Android's history availability and OEM reporting can vary. The app refreshes on launch/resume and at a periodic in-app interval; it does not promise second-by-second background polling.

The app can classify app-level usage as Study, Mixed or Distraction, but Android's standard usage API cannot determine which YouTube video, Telegram chat or Chrome page was used. Mixed apps therefore need your category choice; no page/content inspection is performed. Study-app time is shown separately from total screen-active time so the phone usage total remains truthful. Timer logs and app foreground totals remain separately visible. For the Study component of the Productivity Score, the higher of the two is used rather than adding them, to reduce double-counting where the time periods overlap. This is a conservative estimate, not exact interval reconciliation.

## Focus Guard notes

Blocking and daily app limits are enforced only while Focus Guard is active. Blocking is optional and uses Android AccessibilityService after a separate disclosure and affirmative consent. It checks the foreground app package only and does not read screen content. User can always take an emergency 5-minute pass or end the focus session. Google Play imposes an Accessibility API declaration and policy requirements on this use; review current policy before Play Store publication. This pack does not guarantee Play approval or identical behavior across all OEMs.

## Cloud

Daily summaries live inside `appData.digitalWellness`. Existing Firebase authentication and Firestore account document are reused. PC browser displays synced snapshots; native UsageStats is only available on Android. PC `app.js` was extended to preserve the new nested Wellness maps during cross-device merges.

## Default baselines

The initial personal targets are 6 hours study, 5 hours screen-active time and 60 minutes distraction. These are editable starting values only; change them on Digital Wellness to match your routine.
